# Maestro is the session, not a subagent

## Question

The orchestrator dispatches work to builders, reviewers and researchers. Is it
one of the crew, spawned like the rest, or is it the top-level session itself?

## Decision

The top-level session. There is no `maestro.md` role sheet that gets spawned;
the session the human is talking to *is* Maestro.

## Why

Subagents cannot spawn subagents. This was a design inference and is now a
measured fact: in the reference deployment's first wave a spawned orchestrator
found the spawn tool disabled inside subagents and could only hand a dispatch
plan back to its parent (`docs/RECONCILIATION.md`, G0a).

The degrade path matters as much as the rule, so it is written down: an
orchestrator without spawn ability **surveys, vets, exports status, and returns
a dispatch plan** - unit, key, acceptance, disjoint file surfaces, merge order.
The parent session executes it. The failure this prevents is a plan reported as
though it were a dispatch: work that everyone believes is running and nobody
started.

## What this rules out

- Recursive crews. Depth is one: session dispatches agents; agents do not
  dispatch agents.
- Any timer, check-in or follow-up registered by a subagent. Those fire into the
  parent, so the agent that scheduled one waits forever while its wake-up wakes
  somebody else. Only the session schedules (`docs/RECONCILIATION.md`, G3).

## Revisit if

The harness gains real nested spawning with its own budget accounting - and
even then, the degrade path stays, because a crew that only works on the newest
harness is a crew that stops working.
