# One source of truth, derived presentations, reporting rides existing actions

## Question

The wall's readers are multiplying — the served page, a phone status
card, a human CLI summary, MCP tools for agents, the live agents feed.
Does each get its own writer, its own schedule, its own copy of the
facts? An AI engineering team makes the wrong answer expensive twice:
every extra reporter is tokens and actions spent re-copying state, and
every extra copy is a place for the copies to disagree.

## Decision

The Patron's direction (2026-09-20, verbatim): *"we want to make sure we
don't have too many cooks providing different information. and since
we're using an AI engineering teams we want to limit reporting use of
tokens or actions as much as possible, and keep shared sources of truth.
shared pipeline and integration points to keep everything as simple as
possible."* Four binding clauses:

1. **One written truth, everything else derives.** The tracker (the
   host's board, or the kit's event ledger where the kit is the
   tracker) is the only written source. The wall page, `wall summary`,
   the phone card, and every MCP tool are read-only projections of the
   same derived snapshot — none is ever written independently, and none
   invents a fact the snapshot doesn't carry.
2. **One implementation per fact.** A fact rendered in two places is
   computed in one: `summary.build_summary` backs both the human CLI
   and the agent-facing MCP `wall_status`; the status vocabulary and the
   enqueue payload live in `contracts.py`, with the template's JS tables
   as a **pinned mirror** (the page must stay static), never a second
   authority — the tests assert the mirror against the module.
3. **Reporting rides existing actions.** No scheduled run, agent, or
   trigger whose only job is to re-copy state. A status surface updates
   as a by-product of the pipeline action that changed the state (the
   courier tick that already renders; the merge step that already flips
   the board). Standing token spend on reporting is rejected by
   default.
4. **A new channel must name its derivation.** Before adding a reader
   or reporter: which source of truth does it derive from, and which
   existing action does it ride? A channel that needs its own writer or
   its own schedule fails this test and needs a DEC superseding this
   one.

## Why

Drift between reporters is not a cosmetic bug — a human and an agent
acting on different numbers make conflicting decisions that each look
locally correct. It is the same class [`RECONCILIATION.md`](../RECONCILIATION.md)
records for shared git state (two writers, one resource, silent
divergence), applied to reporting: one authority, pinned mirrors,
never two authorities. And in an agent workforce, reporting is metered work:
a cron that re-states an unchanged board burns budget the wave could
have spent building. Deriving every presentation from one snapshot
makes disagreement structurally impossible and makes the reporting cost
of a new surface approximately zero.

## Revisit if

- A surface genuinely needs facts the snapshot cannot carry (then:
  extend the snapshot, not the surface).
- A derived presentation needs freshness the ride-along cadence cannot
  give (then: pull-at-open beats push-on-schedule; a schedule is the
  last resort and needs the superseding DEC).
