# Researcher network access defaults to none

## Question

Open question 10, flagged as needing an answer before the first real run. The
source outline has researchers searching the internet. The operating preference
is local-only without permission. Which wins, and how is it expressed?

## Decision

Configuration, with a conservative default. `wall.json` carries:

```json
{ "research": { "network": "none" } }
```

Valid values are `none` (default), `allowlist`, and `session-default`.
Whichever mode is in force, the Researcher **states in its findings which mode
it ran under**.

## Why

The default is the decision. A capability that is on unless somebody turns it
off gets used by the first agent that finds it convenient, and nobody
remembers authorizing it.

Three modes rather than a boolean because the honest answer differs by
environment. A hosted session may already have network access through a managed
proxy, and pretending otherwise is theatre. A local box should match the
project's own outbound conventions - typically an explicit allowlist, because
the thing being guarded is not bandwidth, it is an agent reaching an arbitrary
host on the strength of text it read somewhere.

Stating the mode in the findings is the part that makes this auditable. A
finding sourced from the open internet and a finding sourced from the repository
are different evidence, and six weeks later nobody can tell them apart unless
the researcher said so at the time.

The three-mode shape and the default come from `docs/RECONCILIATION.md` Q10,
which is also where the "state the mode in the findings" requirement was added.

## What this rules out

- Silent network access.
- A finding whose provenance is unrecoverable.

## Revisit if

An allowlist proves to need per-item scope rather than per-repository scope - in
which case the mode moves into the dispatch brief, and the default stays `none`.
