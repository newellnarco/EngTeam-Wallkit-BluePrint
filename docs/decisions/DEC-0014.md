# Scoped CI only where escape-rate-validated; the pyramid gates the merge

## Question

The distributed standard proposes scoped test rings per PR with the full
suite on a weekly schedule only. The kit (and the reference deployment's own
scar: a scoped draft lane let broken work through green three times, and the
scope was retired in code) holds that the full pyramid gates the merge.

## Decision (the Patron ruled, 2026-09-19)

The kit's rule stands. Scoped runs are permitted only where their escape
rate is measured and acceptable; the **full pyramid runs at the ready flip
and gates the merge**; a scheduled full run remains the backstop that makes
any scoped selector safe; a scope that lets broken work through green is
retired **in code**, not config.

## Why

The weekly-only proposal saves minutes by spending mainline integrity — the
exact trade the retired-scope incident priced. FAST_TRACK's meter-economics
rules already capture the legitimate half of the cost concern.

This upholds the reconciliation record's measured class (docs/RECONCILIATION.md: a scoped lane's green is not the gate) rather than amending it.

## Revisit if

A blast-radius matrix (TESTING_STANDARDS) accumulates enough escape-rate
data to prove a named scope safe for a named change class.
