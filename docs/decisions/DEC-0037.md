# One resident wall host per machine: MCP for every repo and the sweep, reached through Claude Code's local scope

## Question

DEC-0036 made loopback HTTP possible and left hosting to the adopter
("nothing in the kit starts it"). On the reference deployment nothing did.
Every Claude Code session opened in a repo with the two stdio seats
(engineer and agent) in its `.mcp.json` still started two interpreters. On
top of that, the machine timer started `sweep_all.py` every two minutes,
plus one `wall run-once` interpreter per registered repo: about 20 starts
every ten minutes with three repos. The owner asked (2026-09-28) for the fix
to live in the kit, not in a host repo, because host repos vendor the kit
verbatim (a parity test pins it). The fix also has to leave cloud sessions
working. They have no local server, so an HTTP-only `.mcp.json` would lose
the wall there. Who starts the shared server, how do local clients find it
without a committed config change, and what happens to the timer?

## Decision

The Patron (owner request, 2026-09-28): **the kit ships the host, opt-in
and consent-gated, as one resident process per machine.**

1. **One process, every registered repo.** `tools/wall/host.py` serves the
   DEC-0036 transport for every repo in `~/.wall/registry.json` from one
   loopback port (default 8124), one path per repo and role:
   `/r/<name>/mcp/<role>`. `GET /health` answers liveness JSON. `/health`
   reports ok only while the sweep is on time, so a wedged host reads as
   down. A name that two registry rows share serves neither; the host never
   guesses which repo was meant. It serves the same `handle_request` as
   stdio, so every DEC-0019 clause holds unchanged.
2. **Single instance by construction.** The listener binds exclusively:
   `SO_EXCLUSIVEADDRUSE` on Windows, where `SO_REUSEADDR` would let a
   second process share the port. A second host exits 0 without serving.
3. **The courier sweep folds in, and its behavior does not change.** The
   host sweeps on the timer's old 120 s cadence and writes the same
   heartbeat, log lines and registry pruning. A repo is swept in-process only
   when its vendored `tools/wall/` is byte-identical to the code the host
   runs. Otherwise its own `wall.py` runs in a subprocess, exactly as the
   sweeper did.
4. **The timer becomes the watchdog, not a second sweeper.** It is re-timed
   to 300 s. While the host answers `/health` with ok, `sweep_all.py` exits
   at once. When it does not, the sweeper sweeps as before and starts the
   host detached. The sweeper's one connection is that probe: a literal
   `127.0.0.1` URL with proxies bypassed. `test_sweeper_makes_no_network_call`
   is narrowed to exactly that and still bans every other client.
5. **Local clients reach it through Claude Code's LOCAL scope, never through
   the committed config.** `.mcp.json` stays stdio. On a machine running the
   host, `wall host install` / `wall host link` writes local-scope entries
   (`~/.claude.json`, `projects[<path>].mcpServers`), one per stdio wall
   entry in the repo's `.mcp.json`, under the **same name** and with the
   **same role**, pointing at the host. Claude Code resolves a name defined
   in several scopes local first, then project, then user. So sessions on
   this machine use the host and start no stdio copies, and every other
   machine is unaffected. The writer is idempotent, preserves every other
   key, never overwrites an entry it did not write, refuses a config it
   cannot parse, and reuses Claude Code's own spelling of the project key.
6. **Only link a live host.** Install links nothing and leaves the timer's
   cadence alone until the host has answered. `link` refuses while it is
   down. `wall doctor` fails the `host` check when an enabled host does not
   answer, and names the two fixes: `wall host start`, or `wall host
   uninstall` to return to stdio.
7. **Fully reversible.** `wall host uninstall` removes every local-scope
   entry pointing at the host, in every project. It deletes `host.json`; the
   host sees that and exits within seconds. It restores the timer to 120 s.
   The kit never edits a committed file for any of this.
8. **Upgrades restart the host.** When the kit it runs from changes on disk,
   the host closes its port and starts a fresh copy of itself.

## Why

Per-client stdio is the only design that works everywhere with nothing
running, so it stays the default and the committed config. The cost is
paid on the one machine that has many clients open, and that machine is
also the one that can run a host. Local scope is Claude Code's own
per-user, per-project override. Using it keeps the change on that machine,
keeps the server names (so permissions and prompts that name `mcp__wall__*`
tools keep working), and needs no host-repo edit, so vendor parity stays
green.

Folding the sweep into the same process removes the other multiplier, and
the fingerprint rule keeps "same behavior" literal rather than approximate. It also avoids the
RECONCILIATION class DEC-0019 named (N copies, N drifts): a second sweep
implementation would be a copy that can drift, and the host has none. It
calls the same `wall run-once`, or the repo's own.
A repo on another kit version still gets its own code.

The timer stays because the host can die. A dead host with no watchdog is
the invisible failure `service.py` already names: a stale wall looks like
a quiet project.

## What this rules out

- Rewriting a repo's committed `.mcp.json` to HTTP (it breaks every machine
  without the host) or adding HTTP entries under new names (both servers
  would run, and nothing is saved).
- A host that binds beyond loopback, or a shutdown endpoint. Stopping the
  host is a file the owner controls (`host.json`), not a request anyone on
  the machine can send.
- Running a different kit version's sweep in the host's interpreter.
- Linking a client to a host that is not answering.

## Revisit if

- Claude Code changes scope precedence, or where local-scope servers live.
  The writer's tests pin the shape, not the client, so this would surface
  as a field report. Re-check it against the MCP scopes documentation when
  touching `mcp_local.py`.
- An MCP client other than Claude Code needs the same (Cursor's
  `~/.cursor/mcp.json`, VS Code user settings): a writer per client, named
  in its own decision.
- Linux/macOS adopters want the watchdog to own the host. systemd and
  launchd reap processes the timer's unit starts, so today the host runs
  there as its own user service.
- The machine desk in `FLEET_COORDINATION.md` is built. It is the same
  resident process and the same `/r/<name>/` mount, and should reuse this
  host, not start a second one.
