# Courier is a script, not an agent

## Question

Consolidation runs every couple of minutes: merge event shards, order them,
render the wall, write a heartbeat. Should that be an agent invocation, or code?

## Decision

Code. `tools/wall/courier.py` is stdlib Python with zero model calls, and the
crew has no role that does consolidation.

## Why

Two independent reasons, either sufficient.

**Reproducibility.** The ledger's value is that a full rebuild from shards
yields a byte-identical result to an incremental run - merge is idempotent on
`event_id` and totally ordered on `(ts, session_id, seq)`. A model in that path
can silently drop, reorder or paraphrase a record, and the property is gone. An
audit trail you cannot reproduce is not an audit trail.

**Cost.** A model waking every two minutes to count tokens and render a grid
outspends the agents doing the actual work while producing no code. Bookkeeping
is deterministic; models are for judgment - contradiction triage, stale-claim
narration, anomaly.

Confirmed in production: the reference deployment ran status streaming all night
as one Python file pushing an isolated branch, with zero model calls
(`docs/RECONCILIATION.md`, G0c).

## What this rules out

- A "Foreman" process that polls. The Foreman's singleton is a lock file, not a
  running agent.
- Any design where the ledger is written by something that can be wrong about
  what it read.

## Revisit if

Consolidation ever needs a judgment call that cannot be expressed as a rule -
in which case the judgment becomes a separate, explicitly-invoked agent that
*reads* the ledger and writes its opinion as an event, and the merge stays code.
