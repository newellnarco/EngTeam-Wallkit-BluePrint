# Drift-first: the docs pass precedes dispatch, for the Architect and every role

## Question

The platform's documents of record (process docs, diagrams, role
instructions, decision log) were being reconciled *reactively* — drift
was found when someone asked, not before someone built. Twice in one
day the Patron's questions ("is the architect documenting all these
designs?", "where does MCP fit in our roles?") surfaced real drift a
build was about to ride over: a CLI section missing a shipped command,
an architecture diagram missing three components, a role boundary
nobody had written down.

## Decision

The Patron's direction (2026-09-20, verbatim): *"looking for drift,
updating and add or remove platform docs and diagrams and instructions
should always be the first part the architect does so that the builders
know what they're building and the maestro always knows and sequence,
dependencies, order of operations, etc...this should be SOP for the
team, and each role."* Three binding clauses:

1. **The Architect's first act in any wave or arc is the drift pass:**
   audit the platform docs, diagrams and instructions that the coming
   work touches against what is actually built; update, add or REMOVE
   (a stale document kept is drift with a byline); emit `doc_impact`
   for any change that invalidates work built against the old version.
   Only then are stories written and dispatch briefs cut — so builders
   build from current documents and the Maestro sequences from current
   dependencies and order of operations, never from memory of them.
2. **Each role carries the same discipline at its own scale (G15):**
   the first act on taking any surface is reading its documents of
   record; drift found there is REPORTED (to the Architect via the
   question queue, or fixed in-scope when the role owns the document)
   — never silently built over, and never silently patched outside the
   role's authority.
3. **The session-start SOP gains the pass explicitly:** before
   dispatch, the Maestro confirms the drift pass covered the surfaces
   this session will touch, or runs it. A session that dispatches from
   stale documents re-learns clause 1 the expensive way.

## Why

Documents of record are the only channel this organization is allowed
to coordinate through (agents share no memory; DEC-0018 forbids side
channels). A builder working from a stale diagram is not "mostly
right" — they are building a different system that happens to share
file names with this one, and the drift compounds silently until a
review or a Patron question catches it. Paying the audit cost FIRST is
the cheap ordering: docs are small, builds are large, and the pass also
produces exactly the sequence/dependency picture the Maestro needs for
dispatch anyway.

## Revisit if

- The drift pass becomes the bottleneck of small waves (then: scope it
  to touched surfaces, which clause 1 already permits — never skip it).
- Tooling can diff docs against built reality mechanically (then the
  pass gains a `wall`-style checker and the SOP points at it; the
  ordering rule itself stands).
