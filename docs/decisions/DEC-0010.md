# One machine-wide timer, not one per repository

## Question

`wall install` needs the courier to run on a schedule. Register a timer per
repository, or one timer per machine that walks a registry?

## Decision

One scheduled task per machine. It wakes on its interval, walks
`~/.wall/registry.json`, and runs consolidation for each live repository. A
repository whose path no longer exists is dropped automatically.

Installing the wall in a tenth repository creates nothing new: it appends a line
to the registry.

## Why

**Orphans.** Ten repositories means ten scheduled tasks, and a scheduled task
outlives the directory it points at. An orphan firing every two minutes forever
and failing silently is the worst shape of failure available here, because
nothing reports it.

**Quotas are account-level.** Model and platform quotas are not per repository.
A per-repository wall structurally cannot show true remaining budget; the
machine-wide walker can, and the cross-repository rollup comes free.

**Consent.** Registering a persistent background service is exactly what a
local-only operating preference guards against, so it happens once per machine
on explicit say-so, and the session-start hook **detects only** - it never
writes a system task. After the first yes, adding a repository is a plain file
write needing no further approval.

The dead-timer failure mode is covered separately and deliberately: the courier
writes a heartbeat on every run whether it succeeded or not, the wall renders
that timestamp and goes red past five minutes, and the session-start hook
surfaces a stale heartbeat rather than letting a frozen grid be read as truth.

Settled during design and unchanged by the reconciliation, which touched only
the serving half of it - `docs/RECONCILIATION.md` Q14 adds that a host already
serving a wall should have the kit's files registered with it rather than
getting a second server, and that either way the server binds the loopback
address explicitly and sends no-cache headers on the polled JSON.

## What this rules out

- A timer created without a human saying yes.
- A second server standing up beside one the host already runs.
- A wall that looks healthy because nothing has run.

## Revisit if

A platform makes per-repository scheduling safe from orphans and exposes
per-repository quota, which would remove both reasons at once.
