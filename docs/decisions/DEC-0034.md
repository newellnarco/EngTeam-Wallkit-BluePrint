# The owner runs a diagnostic by hand only while no closed loop exists

## Question

Mined experience from earlier deployments allowed one exception to "never
ask the owner to run anything": ask for a hand-run diagnostic once, then
automate it. The kit (`DIAGNOSTICS_LOOP` section 6, `BEST_PRACTICES` 3.13)
allowed only "look", plus a step whose missing channel is named. Is a
hand-run diagnostic ever an acceptable ask?

## Decision

The Patron (2026-09-23): *"only if there is no established closed loop
between the dev environment to the repo for telemetry and logs."*

1. **While a closed loop exists, never.** When the dev or target
   environment already ships telemetry and logs back to the repository (the
   shipper and freshness contract of `DIAGNOSTICS_LOOP` sections 1-2), a
   diagnostic question is answered from that channel, or the channel is
   extended to carry it. It is never handed to the owner.
2. **While no closed loop exists, one hand-run diagnostic may be asked.**
   The ask names the loop that is missing, and building that loop is filed
   in the same breath as a P1 item. It is the bootstrap for the loop, not a
   standing way of working.
3. **A question asked by hand a second time is a defect**, whether or not
   the loop exists yet: the probe becomes a collector
   (`SKILLS_LIBRARY` 1.22).
4. **"Look" is unchanged.** Verification by looking (`DIAGNOSTICS_LOOP`
   section 5) was always allowed and stays allowed.

## Why

RECONCILIATION grades every claim by whether it was measured; a diagnosis
with no channel to measure through has nothing to grade. The rule protects the
owner's time, but a crew with no telemetry channel at all cannot diagnose
anything without one first look at the machine. Refusing
that look does not build the channel; it stalls the diagnosis. Allowing it
only while the channel is missing, and only with the channel filed, keeps
the ask from becoming a habit.

## What this rules out

A hand-run diagnostic on a system whose telemetry and logs already reach the
repository; a hand-run ask with no loop item filed beside it; the same
question asked by hand twice.

## Revisit if

A deployment shape exists where a closed loop cannot be built at all (an
air-gapped target with no return path). Then the exception needs its own
standing form, recorded as an owner decision with a lifting condition.
