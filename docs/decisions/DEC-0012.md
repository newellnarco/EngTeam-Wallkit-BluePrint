# The Integrator is a first-class role

## Question

Between "the builder's unit is finished in its own working copy" and "it is
merged" there is a body of work: rebase onto the moved base, resolve mechanical
conflicts by regeneration, prove the result is safe, re-run the gates, author
the pull request, drive the review threads. Is that part of the builder's job,
or its own role?

## Decision

Its own role, with its own written procedure: `integrator.md`. It is a **hat a
builder assumes** when the single pull-request slot frees, not a separate agent
- same worker, explicit role sheet, one procedure that lives in a file.

## Why

The reference deployment ran this work by re-invoking each builder with a long
hand-written transplant brief. It worked - six units built in parallel, five
merged through one pull-request slot - but the procedure was re-sent five times
and drifted between sendings, once mis-stating where a file lived
(`docs/RECONCILIATION.md`, G11, G13).

A procedure that is re-typed from memory each time is a procedure that decays.
Moving it into a role sheet makes the integration steps quotable, diffable, and
improvable in one place, which matters because the steps are unforgiving in a
specific order:

1. Rebase onto the moved base.
2. Regenerate derived files with their tools; never hand-merge them.
3. Run the safety proof - a path-filtered diff of the designated ref against the
   base must show only content that belongs to this unit plus what is already
   merged.
4. Re-run the gates **last**, after the final edit.
5. Open the pull request as a draft; report green; stop.

Merge authority stays with the coordinator (`RULES.md` operating rules): the
Integrator's output is a green draft, not a merged change.

## What this rules out

- Hand-merging a derived file.
- Running gates before the last edit and calling the result a gate.
- An integrator that merges its own work.

## Revisit if

Parallel pull-request slots become available, which would change the
serialization but not the procedure - the rebase, the proof and the gate order
are what they are.
