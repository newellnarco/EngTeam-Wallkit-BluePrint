# Draft-PR auto-review is a pinned per-lane choice, default OFF for metered lanes

## Question

A distributed engineering standard mandates reviewer feedback on draft pull
requests (catch findings early); fleet evidence from a sibling deployment
shows drafts are where automated review burns the most quota for the least
value. Which default does the kit carry?

## Decision (the Patron ruled, 2026-09-19)

Neither side becomes a universal rule. Draft-review is a **per-lane setting
recorded in the repo's REVIEWER_LANES register**, defaulting **OFF for
metered lanes** and free to be ON for unmetered ones. Changing it is a
register edit with the lane's meter facts beside it, not a philosophy debate.

## Why

Both positions are measured and both are local truths about *specific
lanes*. A per-lane pin preserves the evidence either way; a global default
would overwrite one deployment's scar with another's.

The per-lane register is the RECONCILIATION G7 lane-posture discipline extended to a config choice.

## Revisit if

A lane's meter shape changes (throttle -> hard stop or pricing change), or a
draft-caught defect class emerges that the ready-flip review demonstrably
misses.
