# Names bind to the agent instance, not to the role slot

## Question

Open question 13. Should builder slot one always be Desmond across sessions, or
should a name belong to a particular invocation and be released afterwards?

## Decision

Bind to the instance. A name is allocated when an agent starts, held while it is
live, and released when it ends.

## Why

Slot binding reads better in reports - the same crew every day - and that is
exactly what makes it dishonest here. Subagent invocations share no memory. A
second Desmond knows nothing the first one learned, and a surface that presents
them as one continuing worker invites both the human and the next agent to
assume continuity that does not exist.

Instance binding costs nothing, because cross-session reporting joins on the
**key**, not the name (DEC-0003). Everything a slot would have given is
available by querying the key history; the name is only ever a label for the
thing currently running.

Kept deliberately rather than by inertia: `docs/RECONCILIATION.md` Q13 revisited
it after the first live wave and confirmed the current implementation.

## What this rules out

- Talking about "the builder" as a persistent worker with history.
- Any report that joins runs by display name.

## Revisit if

The crew ever gains genuine per-role memory that survives a run - at which
point a slot is an honest description of something real, and the decision
changes for the right reason.
