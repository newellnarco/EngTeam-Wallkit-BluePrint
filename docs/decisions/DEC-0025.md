# The Warden's data charter: exposure, regimes, states — continuous, and forward

## Question

The Warden ruled on declared data uses and signed architecture, but the
charter never named WHERE data actually sits (in a hosted LLM's prompt, in
container layers, loose on a network, in public), WHICH regimes bind it
(PII, PHI, PCI, GDPR, government/law-enforcement reach, sector rules), or
its STATES (at rest, in motion, in use). And the Warden's presence was
gate-shaped — architecture sign-off, dispatch verdicts, wave-close audit —
when the cheapest places to prevent a data liability are earlier: at
requirements, during technology selection, and when test data is designed.
Where does the Warden stand across the lifecycle, and what is a ruling's
default shape?

## Decision

`docs/DATA_PROTECTION.md` is the Warden's data charter, binding four things:

1. **The exposure map** — every declared data use names where the data is on
   the ladder walled / containers / in-the-LLM / loose-on-a-network /
   public. A prompt to a hosted model is an egress to a third party; local
   inference keeps it walled; movement down the ladder is always a Warden
   question.
2. **The regime table** — classification names the regime (PII, PHI, PCI,
   government/law-enforcement reach, regulated-industry, contract-bound)
   and its residency/jurisdiction. The host names ITS regimes at intake;
   the Warden never guesses jurisdiction; the strictest obligation wins.
3. **Three states, all evaluated** — at rest, in motion, and in use
   (prompts, logs, fixtures — the leakiest state and the least audited).
4. **Six checkpoints, continuous** — requirements, technology selection,
   architecture, test development, building, before release. Not a gate at
   the end and not a full stop at any of them: **the default deliverable at
   every checkpoint is the compliant way forward for this host** — its
   rules, environment, industry, country, cloud-or-local, LLM setup — drawn
   from the catalog (minimize, synthesize, mask/tokenize, encrypt, segment,
   localize, paper). `refused` remains, and keeps its shape: no compliant
   path as declared, smallest redesign named in the same ruling.

Block-without-grant is unchanged: the Warden can still refuse autonomously
and can never widen access; this decision shapes the default output, not the
ceiling.

## Why

Patron direction, 2026-09-21. The reconciliation record's standing lesson —
evidence over self-report (G0b) — applies to data exactly as to status: "we
handle it carefully" is a self-report, while an exposure row, a named
regime and a state are checkable facts. The existing verdicts already
carried the seed ("anything an agent sends to a model prompt is a data use");
this ruling generalizes that seed into a map, and moves the Warden upstream
to the three checkpoints where prevention is cheapest and silent creation is
likeliest.

## Revisit if

- A regime the table lacks recurs across adoptions (the sixth-family rule of
  DEC-0024 applies here too — graduate it).
- The checkpoint load measurably bottlenecks waves whose arcs carry no data
  surface — tighten the routine-tier fast path rather than the charter.
- A host operates fully air-gapped with local-only inference — checkpoints
  collapse toward 4 and 6, and the charter should say so in one line for
  that profile rather than being waved.
