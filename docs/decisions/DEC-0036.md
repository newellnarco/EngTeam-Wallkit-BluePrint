# The wall speaks MCP over stdio or loopback HTTP: six tools, role by path, still never remote

## Question

DEC-0019 made the MCP server stdio-only. On the reference deployment that
means every MCP client session (Claude Code CLI, Claude Desktop, an agent
harness) spawns its own copies of `mcp_server.py`: two interpreters per
session, because the engineer and agent seats are separate `--role`
processes. The box owner reported "many Python processes eating memory and
CPU" (2026-09-27), and asked for one shared server that every client on the
machine attaches to. Does a second transport cross the line DEC-0019 drew?

## Decision

The Patron (2026-09-28): **allow MCP Streamable HTTP on the loopback
interface, as a second transport beside stdio.** DEC-0019's clauses 1, 2, 4
and 5 carry over unchanged — the same six tools, the same captured CLI, the
same role allowlists, failures as results. Clause 3 is replaced by:

1. **Stdio stays the default** and the only transport a fresh adoption
   configures. A client that cannot reach a local server (a cloud session, a
   CI runner) keeps working exactly as before.
2. **HTTP binds loopback only, structurally.** `make_http_server` refuses any
   host that is not `localhost` or a loopback address; there is no flag that
   widens it. Remote exposure — what claude.ai custom connectors need — is
   still out and still needs its own decision with an auth story.
3. **The role is the path.** `POST /mcp/engineer` serves all six tools;
   `POST /mcp/agent` serves the four reads; an unknown role degrades to
   `agent`, never up. `--role` does not apply to `--http` and is refused
   with it. **This is a configuration convention, not an authentication
   boundary** — exactly as over stdio, where any local process could already
   start `mcp_server.py --role engineer`. The role gate keeps a correctly
   configured agent out of the human verbs; it does not stop a local process
   that chooses to lie. Anything stronger (a per-seat token) is a new
   decision.
4. **Browser pages cannot reach it.** Every browser request carries an
   `Origin`; MCP clients that are not browsers send none. A request with an
   `Origin` is refused unless the operator allowed that exact origin
   (`--allow-origin` / `allow_origins`) — a page served from localhost (a dev
   server, a notebook) is a browser too and gets no seat stdio never gave it.
   The `Host` header must also be a loopback name (DNS-rebinding defence in
   depth). *(Amended 2026-09-28 after review: the first cut admitted any
   loopback origin.)*
5. **Stateless and pull-only.** JSON responses to POSTs, `202` for
   notifications, `405` for `GET` (the server never pushes) and for
   `DELETE` (there is no session to end). Only CLI-capturing tool calls
   share a lock (a `wall_answer` ledger write must not interleave), and the
   capture is per thread, so a host process printing on another thread can
   neither leak into a transcript nor lose its own output. Idle connections
   time out; handler threads are joined on close so an in-flight answer
   finishes its write.
6. **Hosting is the adopter's choice.** The kit ships `make_http_server`
   (for a resident host process to run on a thread) and `--http
   [HOST:]PORT` (to run it standalone). Nothing in the kit starts it.

## Why

The cost DEC-0019 did not see is per-client processes: on a machine with
several MCP clients open, stdio multiplies interpreters by clients by roles.
A loopback listener is one process for all of them, and it does not change
who can do what — the exposure boundary DEC-0019 protected is the network
edge, and that is kept by construction, not by configuration.

Nor does it bring back the RECONCILIATION class DEC-0019 named (N copies,
N drifts): both transports dispatch into the same `handle_request`, so the
stdio seat and the HTTP seat cannot disagree about a tool, a schema or a
refusal.

## What this rules out

- Binding `0.0.0.0`, a LAN address, or a hostname — even behind a flag.
- A server-sent event stream, sessions, or any server-initiated message.
- Choosing the role from a header or a query string; the path is the one
  thing every client configuration can express and every log records.

## Revisit if

- claude.ai-direct access is wanted (remote transport DEC: authentication,
  exposure boundary, which tools survive the trip).
- A client needs server-initiated messages (progress, sampling): that is the
  SSE half of the transport and a new decision.
- MCP's Streamable HTTP framing changes in a way the stdlib subset misses
  (the tests speak it against a real server, so this surfaces as a failure).
